- ไม่มี horizontal overflow ที่ 320 / 375 / 768 / 1440 px ทั้ง Light และ Dark

- ข้อความยาว (หมายเหตุ 300 ตัว, ชื่อสมุดยาว, ชื่อผู้ใช้ 100 ตัว) ไม่ทำเลย์เอาต์พัง ที่ 320px
- ข้อมูล 3,000 รายการ: สลับหน้าใน ~50 ms (ฐานข้อมูลจำลอง)

- ลบบัญชี: ข้อมูลถูกลบ/ไม่ระบุตัวตนตามที่ออกแบบทั้งเจ้าของและสมาชิก
- Rules: 27/27 ผ่าน; คนนอกอ่านสมุดไม่ได้

## ประเด็นที่พบ

### 🔴 High

**BUG-01 — บันทึกรายการล้มเหลวแบบเงียบ และล้างสิ่งที่ผู้ใช้กรอก**
- *ขั้นตอน:* เมื่อเซิร์ฟเวอร์ปฏิเสธการเขียน (สิทธิ์/ข้อมูลไม่ผ่านกฎ/ออฟไลน์นาน) แล้วกด "บันทึกรายการ"
- *ผลจริง:* ช่องจำนวนเงิน/รายละเอียดถูกล้างทันที ไม่มีข้อความผิดพลาด ไม่มีแฟลช "บันทึกแล้ว" ผู้ใช้ไม่รู้ว่าข้อมูลหาย (เกิด unhandled promise rejection ในคอนโซล)
- *ควรเป็น:* คงค่าที่กรอก แสดงข้อความผิดพลาด ให้ลองใหม่ได้
- *สาเหตุ:* `AddForm.handleSubmit` เรียก `onSubmit` แล้วล้างฟอร์มเลยโดยไม่รอผล; `App.handleAdd` ไม่มี `catch`
- *แนะนำ:* ให้ `onSubmit` คืน Promise, ล้างฟอร์มเมื่อสำเร็จเท่านั้น, แสดง `role="alert"` เมื่อล้มเหลว

**BUG-02 — หน้าโปรไฟล์รับค่าที่ทำให้ "ทุกการบันทึก" ล้มเหลวหลังจากนั้น**
- *ขั้นตอน:* โปรไฟล์ → ใส่ "ลิงก์รูปโปรไฟล์" เป็น `abc` (หรือชื่อยาวเกิน 100 ตัว) → บันทึกโปรไฟล์ → ไปบันทึกรายการ
- *ผลจริง:* Rules ปฏิเสธรายการทุกครั้ง (ยืนยันด้วย emulator: `photoURL 'abc'` ❌, ยาว >500 ❌, ชื่อ 101 ตัว ❌) และเพราะ BUG-01 ผู้ใช้จะเห็นว่าแอป "บันทึกไม่ได้" โดยไม่รู้สาเหตุ
- *สาเหตุ:* `ProfileView` ไม่มีการตรวจ/`maxLength`; รูปแบบที่ rules ต้องการคือ `http(s)://…` ≤ 500, ชื่อ ≤ 100
- *แนะนำ:* ตรวจค่าก่อนบันทึก (URL ต้องขึ้นต้น http/https, จำกัดความยาว) พร้อมข้อความอธิบาย

### 🟠 Medium

**BUG-03 — ฟอร์มรับวันที่ว่างและจำนวนเงินเกินขอบเขต**
- ล้างช่องวันที่แล้วกดบันทึก: ปุ่มไม่ถูกปิด รายการถูกส่งโดย `date=""` (บนข้อมูลจำลองแสดง "NaN" บนหน้าภาพรวม; บน production rules ปฏิเสธแล้วเข้า BUG-01)
- จำนวนเงิน 11 หลัก (เช่น 99999999999) ปุ่มยังกดได้ แต่ rules จำกัด `< 1,000,000,000` → ล้มเหลวเงียบ
- *แนะนำ:* ปิดปุ่มเมื่อวันที่ว่าง/ไม่ถูกต้อง และจำกัดจำนวนเงินสูงสุดฝั่ง UI ให้ตรงกับ rules พร้อมข้อความ

**BUG-04 — Viewer เห็นปุ่มลบรายการ แต่กดแล้วไม่เกิดอะไร**
- ผู้ใช้สิทธิ์ดูอย่างเดียวเห็นไอคอนถังขยะและกล่องยืนยัน หลังกด "ลบรายการ" ไม่มีอะไรเปลี่ยน ไม่มีข้อความ (error `คุณมีสิทธิ์ดูอย่างเดียว…` ไปโผล่แค่ในคอนโซล)
- *แนะนำ:* ซ่อนปุ่มลบเมื่อไม่มีสิทธิ์ (ส่ง `onDelete` เฉพาะ Owner/Editor) และจับ error จาก `onDelete`

**BUG-05 — กล่องโต้ตอบไม่มี focus trap**
- เปิดกล่องยืนยันลบ/ลบบัญชีแล้วกด Tab → โฟกัสหลุดไปองค์ประกอบด้านหลัง; ปิดแล้วโฟกัสไม่กลับไปที่ปุ่มเดิม (Esc ปิดได้ ✅)
- ผู้ใช้คีย์บอร์ด/screen reader จะสับสน (WCAG 2.4.3)
- *แนะนำ:* วน Tab ภายในกล่อง, คืนโฟกัสเมื่อปิด (หรือใช้ `<dialog>`/ไลบรารี focus-trap)

## ข้อสังเกตด้านประสิทธิภาพและต้นทุน

- Listener ของรายการดึง **เอกสารทั้งหมด** ทุกครั้งที่เข้าแอป (ไม่มี pagination) ฝั่งจอไม่ช้า แต่ Firestore คิดค่าอ่านตามจำนวนเอกสาร ผู้ใช้ที่มี 3,000 รายการ = 3,000 reads ต่อการเปิดแอปหนึ่งครั้ง — แนะนำจำกัดช่วงเวลา (เช่น 12 เดือนล่าสุด) หรือเก็บยอดสรุปรายเดือน
- Bundle: Recharts ~534 kB (ก่อน gzip) โหลดตั้งแต่หน้าแรก — พิจารณา lazy-load หน้า Dashboard/Summary
